* Untyped lambda calculus :noexport:
Let $\mathsf{Var}$ be a set of variable names. Define $\mathsf{Term}$ inductively:

\[ \frac{x ∈ \mathsf{Var}}{x ∈ \mathsf{Term}} \quad \text{Variable} \]

\[ \frac{x ∈ \mathsf{Var} \qquad e ∈ \mathsf{Term}}{λ x.\;e ∈ \mathsf{Term}} \quad \text{Function} \]

\[ \frac{f ∈ \mathsf{Term} \qquad a ∈ \mathsf{Term}}{f\;a ∈ \mathsf{Term}} \quad \text{Application} \]

* Adding types: STLC :noexport:
The *simply typed lambda calculus* adds types, defined inductively:

\[ \frac{}{\mathsf{Nat} ∈ \mathsf{Ty}} \qquad \frac{}{\mathsf{Bool} ∈ \mathsf{Ty}} \qquad \frac{A ∈ \mathsf{Ty} \qquad B ∈ \mathsf{Ty}}{A → B ∈ \mathsf{Ty}} \]

Lambda functions now annotate their parameter's type:

\[ λ (x : \mathsf{Nat}).\;x \]

What terms are valid?

* Type contexts :noexport:
A context is a list of variable bindings.

\[ Γ = x : \mathsf{Nat},\; y : \mathsf{Bool} \]

A *typing judgement* has the form:

\[ Γ \;⊢\; e : T \]

“Under the bindings in $Γ$, expression $e$ has type $T$.”

* Variables: look up the context :noexport:
- The *variable rule*:

  \[ \frac{x : T ∈ Γ}{Γ \;⊢\; x : T} \]

- For example, let $Γ ≔ x : \mathsf{Nat},\; y : \mathsf{Bool}$

  \[ Γ \;⊢\; x : \mathsf{Nat} \qquad Γ \;⊢\; y : \mathsf{Bool} \]

* Application uses the same context :noexport:
- The *application rule*:

  \[ \frac{Γ ⊢ f : A → B \qquad Γ ⊢ a : A} {Γ ⊢ f\;a : B} \]

- For example, let $Γ ≔ f : \mathsf{Nat} → \mathsf{Bool},\; n : \mathsf{Nat}$:

  \[ Γ \;⊢\; f\;n : \mathsf{Bool} \]

* A binder extends the context :noexport:
- The *function rule*:

  \[ \frac{Γ,\;x : A \;⊢\; \mathit{body} : B} {Γ \;⊢\; λ (x : A).\;\mathit{body} : A → B} \]

- Example, with an empty outer context:

  \[ \frac{x : \mathsf{Nat} \;⊢\; x : \mathsf{Nat}}{∅ \;⊢\; λ (x : \mathsf{Nat}).\;x : \mathsf{Nat} → \mathsf{Nat}} \]

* Names: shadowing :noexport:
\[ λ (x : \mathsf{Nat}).\;λ (x : \mathsf{Bool}).\;t \]

*Shadowing*: We can't refer to outer $x$ in $t$.

* Bound and free variables :noexport:
- A variable occurrence is *bound* if appears in the context.
- It is *free* otherwise.

\[ λ (x : \mathsf{Nat → Nat}).\; x\ y \]

Inside the body, $x$ is bound and $y$ is free.

* β-reduction: apply a function :noexport:
\[ \frac{Γ,\;x : A ⊢ e : B \qquad Γ ⊢ a : A}{Γ ⊢ (λ (x : A).\;e)\;a \;→_β\; e[x := a] : B} \quad (β\text{-reduction}) \]

$e[x := a]$ substitutes $a$ for the free occurrences of $x$ in $e$, avoiding capture.

Example:

\[ (λ (x : \mathsf{Nat}).\;λ (y : \mathsf{Nat}).\;x)\;7 \;→_β\; λ (y : \mathsf{Nat}).\;7 \]

What if the argument is a variable instead of $7$?

* Names: variable capture :noexport:
We want to replace $x$ with the argument $y$:

\[ (λ (x : \mathsf{Nat}).\;λ (y : \mathsf{Nat}).\;x)\;\underbrace{y}_{\text{free}} \]

\[ λ (y : \mathsf{Nat}).\;\underbrace{\textcolor{red}{y}}_{\text{bound}} \]

*Wrong*: replacing the name directly makes that $y$ bound:


\[ (λ (x : \mathsf{Nat}).\;λ (z : \mathsf{Nat}).\;x)\;y \]

\[ →_β\; λ (z : \mathsf{Nat}).\;\underbrace{\textcolor{green!50!black}{y}}_{\text{still free}} \]

@@latex:\textcolor{green!50!black}{\textbf{Correct}}@@: rename the inner parameter first, then substitute. Complicated and inefficient!

* De Bruijn indices :noexport:
Replace bound names with positions.

- With names: $λ (x : \mathsf{Nat}).\;λ (f : \mathsf{Nat} → \mathsf{Nat}).\;f\;x$
- With indices: $λ_{\mathsf{Nat}}.\;λ_{\mathsf{Nat} → \mathsf{Nat}}.\;\mathbf{0}\;\mathbf{1}$

* Holes
- Purpose: separate *ownership* and *layout*.
- How: Components can have /holes/ that must be filled by their parents.
- The number of holes in a component is tracked in the type so that we can
  statically check that all holes have been filled.

** Why regular lean arguments are not enough?
Consider a list whose footer shows the selected items. \\
The footer needs the list's output, so the list must exist first. \\
As an argument, the footer would be needed before the list (Impossible!).

* Arrange the owned views
#+attr_latex: :options basicstyle=\ttfamily\footnotesize
#+begin_src lean
inductive Layout (Δ : ViewContext) where
  | fill
      (view : ViewRef Δ holes)
      (contents : Fills Δ holes)  -- ≈ Vector (List (Layout Δ)) holes
  | group
      (label : Option String)
      (children : List (Layout Δ))

def Layout.place (view : ViewRef Δ 0) : Layout Δ :=
  .fill view .nil
#+end_src

  E.g. the list, with the summary in its hole.
- =group=: stacks layouts, under an optional label. \\
  E.g. the summary above the list, labelled "Selection".

#+end_src

- Both elaborate to definitionally equal components.
- Names replace positions in both =Γ= and =Δ=.
- The same name can stand for different positions: =ref[rows]= is =.here=, then =.there .here=.

* De Bruijn indices
- With names: $λ (\textcolor{blue!70!black}{x} : \mathsf{Nat}).\;λ (\textcolor{orange!85!black}{f} : \mathsf{Nat} → \mathsf{Nat}).\;\textcolor{orange!85!black}{f}\;((λ (y : \mathsf{Nat}).\;\textcolor{orange!85!black}{f}\;\textcolor{blue!70!black}{x})\;\textcolor{blue!70!black}{x})$
- With indices: $\textcolor{blue!70!black}{λ_{\mathsf{Nat}}}.\;\textcolor{orange!85!black}{λ_{\mathsf{Nat} → \mathsf{Nat}}}.\;\textcolor{orange!85!black}{\mathbf{0}}\;((λ_{\mathsf{Nat}}.\;\textcolor{orange!85!black}{\mathbf{1}}\;\textcolor{blue!70!black}{\mathbf{2}})\;\textcolor{blue!70!black}{\mathbf{1}})$

\bigskip
- An index counts binders from the innermost; =Member= is that count.
  #+attr_latex: :options basicstyle=\ttfamily\footnotesize
  #+begin_src lean
  inductive Member (x : α) : List α → Type where
    | here : Member x (x :: Γ)                       -- 0
    | there (ref : Member x Γ) : Member x (b :: Γ)   -- n + 1
  #+end_src
- Why indices are better as an internal representation:
  - No capture: substituting never requires renaming.
  - No α-renaming: equal terms are syntactically equal.

* Summary
- =state=: private UI state per instance.
- =Γ=: the typed references in scope, with their access.
- =output=: each component can return some value.
- =holes=: places in a view to be filled by the parent.

* Example: a table and its summary :noexport:
:properties:
:beamer_opt: fragile
:end:
#+begin_export latex

lake -q exe forms-web present-table --open
\end{lstlisting}
#+end_export

- Select a row: its description appears in the summary.
- Edit the description: the summary reads the updated output.

The summary consumes the table's row outputs.

We need to create the table before its summary can refer to its output.

But we want to display the summary *above* the table.

* Own a component, get an output and a view :noexport:
#+attr_latex: :options basicstyle=\ttfamily\footnotesize
#+begin_src lean
.own selectionTable <|
  .own (summary .here) <|
    ..
#+end_src

Each =.own= extends two separate contexts:

- The variable context gets a read-only reference to the output.
- The view context gets a reference to the view.

Inside the second body, =.here= refers to the summary in each context.
=.there .here= refers to the table.

* Slots are typed positions too :noexport:
#+attr_latex: :options basicstyle=\ttfamily\footnotesize
#+begin_src lean
abbrev ViewRef (owned : List Nat) (holes : Nat) :=
  Member holes owned

inductive Layout (owned : List Nat) where
  | place (view : ViewRef owned 0)
  | fill {holes : Nat}
      (view : ViewRef owned holes) (contents : Fills owned holes)
  | group (label : Option String) (children : List (Layout owned))
#+end_src

- A view selects a component already owned in this presentation.
- The view context records how many holes each component has.
- A layout arranges views; it does not create component instances.

* The same ownership, two layouts :noexport:
After owning the table and then the summary, the view context is =[0, 0]=.

#+attr_latex: :options basicstyle=\ttfamily\footnotesize
#+begin_src lean
def summaryAbove : Layout [0, 0] :=
  .group (some "Selected items") [
    .place .here, .place (.there .here)]

def tableAbove : Layout [0, 0] :=
  .group (some "Selected items") [
    .place (.there .here), .place .here]
#+end_src

- =.here=: the summary's view.
- =.there .here=: the table's view.

* Build the presentation :noexport:

  : Component [] (List (Item String)) String :=

      .own (summary .here) <|

* Example: two tabs, two private states :noexport:
:properties:
:beamer_opt: fragile
:end:
#+begin_export latex
\begin{lstlisting}
lake -q exe forms-web present-tabs --open
\end{lstlisting}
#+end_export

Two panes share one counter. Each also has a private counter.

1. Increment the first pane's private count.
2. Switch to the second pane and increment its private count twice.
3. Switch back: the first pane retains its count.
4. Increment the shared count: both panes see the change.

Own both panes; use the active tab to choose which view to place.

* Tabs choose a layout :noexport:
#+attr_latex: :options basicstyle=\ttfamily\scriptsize
#+begin_src lean
def sharedTabs : Component [] Nat Nat 0 :=
  .present <|
    .bind (0 : Nat) <|
      .tabs "Panes" (compute%
        => #v["First", "Second"]) <|
        .own (pane (.there (.there .here)) "First") <|
          .own (pane (.there (.there (.there .here))) "Second") <|
            .layout
              (compute%
                value ← .ui (.there (.there (.there (.there .here))))
                => value)
              (compute%
                (active : Fin 2) ← .ui (.there (.there (.there .here)))
                => .group none [
                  .place (.there (.there .here)),
                  #v[.place (.there .here), .place .here][active]])
#+end_src

- =.tabs= binds a writable =Fin 2= and owns the tab strip.
- The two panes remain owned; the layout places only the active pane.


* The component type :noexport:
#+attr_latex: :options basicstyle=\ttfamily\footnotesize
#+begin_src lean
structure Component
  (Γ : Context)
  (α : Type)
  (β : Type := Unit)
  (holes : Nat := 0) where
  LocalState : Type
  node : ComponentNode Γ α LocalState β holes
#+end_src

- =Γ=: references supplied by the surrounding scope.
- =α=: the document value being edited; =β=: the public output.
- =LocalState=: the private state type chosen by this component.
- =holes=: places for content supplied by an enclosing layout.

* The presentation type :noexport:
#+attr_latex: :options basicstyle=\ttfamily\footnotesize
#+begin_src lean
structure Presentation
  (owned : List Nat)
  (Γ : Context)
  (α : Type)
  (β : Type := Unit)
  (views : Nat := 1) where
  LocalState : Type
  node : PresentationNode owned Γ α LocalState β views
#+end_src

- =owned=: components available for placement, indexed by their hole counts.
- =views=: how many layouts it produces. A table row can produce several cells.
- =Component.present= closes a presentation with an empty outer view context.

* Sugar: names for typed references :noexport:
Writing =.there= chains becomes tedious as we add bindings.

- Use names while writing the form.
- Expand those names to typed de Bruijn references.
- Insert shifts automatically when a binding extends the context.

The same namespace also provides notation for bindings and owned.
